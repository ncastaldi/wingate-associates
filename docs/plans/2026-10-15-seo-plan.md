# SEO plan

Date: 2026-10-15. Source: a SearchFit SEO audit (`seo-audit` and `technical-seo` skills) run on the code and on the live site, `https://wingate.associates`. Score 78/100. No critical issues. Work items are GitHub Issues #65 to #71; this file holds the reasoning and the order.

## What the audit found

Passing, and worth keeping:

- `robots.txt` allows all crawlers and names the sitemap. The sitemap lists all four public pages with absolute URLs.
- `www` and `http` both 301 to `https://wingate.associates`. An unknown path returns a real 404.
- Every page has a self-referencing canonical, a unique title, a description, Open Graph and Twitter tags, and the shared 1200x630 image with alt text. No page is `noindex`.
- One H1 per page with a clean H2 and H3 order. The only `<img>` is the 32px logo with explicit size.
- Server components by default, self-hosted fonts with `font-display: swap`, no third-party script except Plausible.
- Edge headers are set: CSP, `X-Content-Type-Options`, `X-Frame-Options`, `Permissions-Policy`.
- No Cloudflare analytics beacon appeared in the live HTML on 2026-10-15, so the Cloudflare RUM item in `CLAUDE.md` may already be done. Confirm in the zone's Speed settings before closing it.

Gaps:

The performance score came from reading the code. Lighthouse and Core Web Vitals were not measured.

## Constraints that shape the fixes

- Plausible is the only analytics (constraint 5). The audit tool's paid monitoring service is not used. No new third-party service without the owner's sign-off and an ADR (constraint 1).
- The CSP allows only the site and the Plausible host. JSON-LD is an inline `application/ld+json` block. A non-JS script type is not executed, but check that `script-src 'unsafe-inline'` (already present) covers it, and do not add any external schema validator call at runtime.
- All copy follows `docs/voice/README.md`: first person, short declarative sentences, no em dashes, no rhetorical questions, none of the banned words.
- Titles and descriptions go through `pageMetadata()` so Open Graph and Twitter stay complete.
- New public pages are added to `src/app/sitemap.ts` by hand.

## Order of work

1. **Structured data (#65).** One JSON-LD block for `ProfessionalService` in the root layout (name, URL, logo, area served Atlanta, LinkedIn in `sameAs`). A `Person` block on About. A `Service` block per service on Services. Keep the data in `src/lib/` next to `site.ts` so the values are not repeated. Add a Vitest test that parses each block and checks required properties. Verify with the Google Rich Results Test after deploy (a manual check, not a runtime dependency).
2. **Home title (#66).** Pass a title to `pageMetadata()` for the home page, about 55 characters, such as "IT Operations Consulting in Atlanta | Wingate Associates". The layout keeps the bare name as the fallback for the 404. Needs the owner's approval of the wording.
3. **Contact description (#67) and sitemap `lastmod` (#68).** Extend the Contact description to 150 to 160 characters. Add `lastModified` to each sitemap entry. Use a fixed date per page that someone updates when the page changes. A build-time date would claim every page changed on every deploy.
4. **Place names in body copy (#69).** Say Atlanta once in the Services intro and once on Home, in the owner's voice. Owner supplies or approves the sentences.
5. **HSTS (#70).** Raise `max-age` at Cloudflare to at least one year. Decide on `includeSubDomains` first. The apex and `www` are the only hosts on the zone today, but confirm nothing else on the zone is HTTP-only. Record the final value in `deploy/README.md`.
6. **Dedicated service pages (#71) and the first case study.** Pages for identity and access cleanup and for the IT operations assessment, plus the role cleanup case study already in progress (`/work/...`). Each gets its own title, description, canonical, sitemap entry and `Service` or `Article` schema. This depends on the owner's answers for the case study and is the highest-value content work.

Items 1 to 5 are small and independent. Item 6 is the real growth lever and is blocked on the owner.

## Out of scope for now

- Keyword tooling, rank tracking and AI-visibility monitoring from hosted services. These conflict with constraint 1.
- Blog or content calendar. Revisit after the first case study ships.
- Hreflang and translation. The audience is English-speaking and local plus remote.

## Success check

Re-run the two audit skills after items 1 to 5 land. Target 90 or above. Check Google Search Console for indexed pages (needs the owner to verify the domain) and watch Plausible for organic search referrals. These tie to open question 1 in `CLAUDE.md`, the success metric beyond "a client or two".
